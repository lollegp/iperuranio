Install iperuranio

Install the skill to read decisions already on your branch. Add the runtime to search by ticket, draft new records and capture decisions through supported agent hooks.

Agent skill Project runtime First decision Questions

Install the agent skill

From the root of your Git project, run the installer and choose your coding agent.

npx skills add https://github.com/lollegp/iperuranio.git --skill iperuranio

To try it on a branch with reviewed decisions, give your agent a ticket and a question.

Use iperuranio to find the decision for ABC-1234. Give the reviewer the record ID, its rationale and the files they should check.

For a manual install, open the skill file and save it as .agents/skills/iperuranio/SKILL.md in a project that supports that directory. The project ZIP includes the skill, CLI and source.

If the checkout has no decision for that ticket yet, the agent should tell you. To start recording decisions, install the runtime below.

Install the project runtime

You need Git, Node.js 24 or later, npm and a POSIX shell. In the project root, install the development dependency and enroll this checkout.

npm install --save-dev git+https://github.com/lollegp/iperuranio.git
npx --no-install iperuranio init
npx --no-install iperuranio doctor

Plain init adds the workflow to AGENTS.md and prints a local MCP launcher. For supported host hooks, run init with your agent’s identifier, such as npx --no-install iperuranio init codex. Each teammate enrolls their own checkout. Inspect the generated project files, reload the agent and approve its project hooks.

Supported adapter IDs are codex, claude-code, copilot-cli, cursor and gemini-cli. An agent that can execute shell commands can use the CLI directly.

Share your first decision

Try this sample in a test checkout. Save the choice and the reason someone else might need later.

npx --no-install iperuranio save "Reduce max-age to 5 minutes." \
  --reason "Product information stayed stale after updates." --ticket ABC-1250

save returns a private candidate ID. Substitute it below. Check the exact English text, then type PUBLISH in the review prompt to create the Markdown file in your working tree.

npx --no-install iperuranio review CANDIDATE_ID
npx --no-install iperuranio search ABC-1250

Commit the reviewed file under .iperuranio/decisions/ and push the branch through your team’s normal review process. A teammate who pulls that commit can ask their agent why the cache lifetime changed. For later revisions, history RECORD_ID follows linked records.

Common questions

Does iperuranio share our original chats?

The shared archive contains reviewed Markdown records. Private candidates stay outside Git on the developer’s device. Capture filters common credentials and email addresses. The developer checks confidential details and whether the wording still reflects the conversation before publication. Everyone who can read the Git repository can read its committed decisions.

Can teammates discuss a decision in different languages?

Yes. The skill asks agents to draft records in English. Teams can also configure a local model for extraction and a second check against the source. During review, compare names of code symbols, quantities, conditions and uncertainties with the original discussion. Publish when the English record preserves the meaning.

Can our agents find each other’s work across branches?

Each agent searches its local checkout. A teammate can retrieve a record once their branch contains the commit that added it. A private candidate ID belongs to its original checkout. Pass a reviewed record ID and commit to another agent when handing off a task.

How do I connect an MCP client?

Run init in the target checkout. Register the command and args from its mcp object as a local stdio server named iperuranio. Keep these machine-specific paths in the client’s local settings. The server provides tools for search, explanations, history, handoffs, challenges and staging candidates.

Will a decision survive an abandoned chat?

Supported hooks process delivered messages while the session runs. Some adapters can also replay unread entries from an available local transcript. The host’s events and transcript retention determine what can be recovered. A skill-only setup relies on instructions. Automatic capture requires a compatible event integration.
